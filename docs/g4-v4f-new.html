What actually changed from v4E to v4F?

F_new adds no physics and reruns no simulation. It preserves both historical versions and makes every requested, implementation-added, numerical, initial-condition and presentation change visible.

Short answer

v4F was not a clean one-factor rerun of v4E. The Git ancestry is correct and the published scalar parameters were retained, but nine relevant changes were bundled. Therefore the dramatic trajectory difference cannot be attributed to steric reaction alone—or to any other single change.

Comparison validity

✓ Correct ancestry

v4F descends from the preserved v4E checkpoint.

✓ Scalar defaults retained

Motor, clutch, cell-drag and guidance values match; v4F adds a 5 s contact-search interval.

✕ Not parent–child OFAT

Mechanics, RNG, initial contacts, contact reach, front selection and update order changed.

△ Within-v4F contrasts

E0–E3 use a common v4F baseline, but the existing timestep, rotation and domain limitations remain.

Scientific wording boundary

Claims we can make

  • v4F repairs several identifiable omissions in v4E.
  • v4F includes two-way contact reaction and current-position contact search.
  • Within v4F, E1 and E2 are single additions to the shared v4F baseline; E3 is the declared combination.

Claims we cannot make

  • “Steric reaction alone changed E0 from 74.8 to 0.4 µm.”
  • “v4F is the same v4E run plus one term.”
  • “The side-by-side v4E/v4F animations use the same seed and network.”

Contract for every future version

1 · Declare one change

Name the exact parent commit and a changed-component allowlist before running.

2 · Freeze the lineage view

Use seed 45, the same geometry, initial contacts and RNG version unless one is the declared variable.

3 · Separate inference

Use matched seeds 41–60 for ensemble inference. Do not choose a new primary seed because its child animation looks typical.

4 · Isolate corrections

RNG, integrator, front-index and initial-condition corrections each become their own microstage and commit.

F_new is an audit record, not a replacement model. Frozen v4E and v4F remain available through the G4 version library.
